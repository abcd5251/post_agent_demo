## 第 1 部分：新使用者指南

### 1.1 這個工具在做什麼？

每天自動幫你「找新聞 → 寫貼文 → 做配圖」，你只要在 Google 試算表上打勾確認，它就會幫你排程發到 Facebook 粉專和 Instagram。

| 步驟 | 誰做 | 做什麼 |
|---|---|---|
| 1. 找新聞 | 自動 | 搜尋你設定的關鍵字（預設「AI Agent」）最近 48 小時的新聞 |
| 2. 寫貼文 | 自動 | 用三種風格各寫一篇：**專業洞察**、**輕鬆有趣**、**行動導向** |
| 3. 做配圖 | 自動 | 每篇貼文各產生一張圖 |
| 4. 放進試算表 | 自動 | 三篇貼文＋圖片寫進 Google 試算表，狀態是「待審核」（`PENDING`） |
| 5. **審核** | **你** | 打開試算表，看內容，可以修改文字或發文時間，**在 `approved` 欄打勾** |
| 6. 排程發文 | 自動 | 把有打勾的貼文交給 Buffer，在指定時間發到 FB／IG，狀態變成「已排程」（`SCHEDULED`） |

### 1.2 每天的運作節奏（台灣時間）

| 時間 | 發生什麼事 |
|---|---|
| 早上 08:00 左右 | 自動產生 3 篇貼文＋3 張圖，放進試算表 |
| 08:00 ～ 15:00 | **你審核並打勾** |
| 下午 15:00 左右 | 把有打勾的貼文排程出去 |
| 當天 19:00 | 「專業洞察」版發出 |
| 隔天 12:00 | 「輕鬆有趣」版發出 |
| 隔天 20:00 | 「行動導向」版發出 |

- 實際執行時間可能比表定晚最多 15 分鐘，這是正常的。
- **沒打勾的貼文永遠不會被發出去。**
- 15:00 之後才打勾的話，當天不會發，要等隔天 15:00 那次（而且發文時間必須還沒過）。

### 1.3 你每天要做的事（只有這些）

1. 打開 Google 試算表的 `posts` 分頁。
2. 看每一列的文案（`copy` 欄）和圖片（`image_preview` 欄）。
3. 需要的話直接修改文字，或修改發文時間（`post_time` 欄）。
4. 確認沒問題的，在 `approved` 欄打勾。

就這樣。其他都是自動的。

### 1.4 如何快速啟用

最簡單的做法：**把[第 2 部分](#第-2-部分給-ai-助手的-prompt)的 prompt 整段複製，貼給 AI 助手（例如 Claude Code），讓 AI 帶你一步一步完成。** AI 會幫你處理安裝和檢查，但下面這些事情需要你本人在網頁上完成（AI 無法代勞）：

#### A. OpenAI（寫文案、產圖）

1. 到 https://platform.openai.com/api-keys 建立一把 API 金鑰。
2. 確認帳戶有儲值（Billing）。
3. 產圖功能可能需要先完成「組織驗證」：Settings → Organization → General。

#### B. Google（存放貼文的試算表）

1. 到 [Google Cloud Console](https://console.cloud.google.com/) 建立一個專案。
2. 在專案裡啟用 **Google Sheets API** 和 **Google Drive API**。
3. 建立一個「服務帳戶」（Service Account）。
4. 幫這個服務帳戶產生金鑰，選 JSON 格式，會下載一個檔案。把這個檔案交給 AI 處理（放進專案資料夾即可，不要把內容貼到聊天視窗）。
5. 建立一個新的 Google 試算表，按右上角「共用」，把 JSON 檔裡的 `client_email`（長得像 `xxx@yyy.iam.gserviceaccount.com`）加為「編輯者」。
6. 試算表網址長這樣：`https://docs.google.com/spreadsheets/d/這一段/edit`，中間「這一段」就是試算表 ID。

分頁和欄位不用自己建，第一次執行會自動建立。

#### C. Cloudinary（存放圖片）

1. 到 https://cloudinary.com 註冊免費帳號。
2. 取得三樣東西：**Cloud name**、**API Key**、**API Secret**。

> **重要（實際踩過的雷）**：API 金鑰必須有「上傳／建立」權限。如果金鑰權限受限，連線檢查會顯示正常，但產完圖要上傳時會失敗，錯誤訊息是：
> `Request forbidden due to missing permissions (actions=["create"])`
> 解法：到 Cloudinary 的 Settings → API Keys 產生一把**完整權限**的新金鑰，換掉舊的。

#### D. Buffer（排程發文到 FB／IG）

1. Instagram 必須是**商業帳號或創作者帳號**（個人帳號不行）。
2. 在 Buffer 連接你的 Facebook **粉絲專頁**（不是個人帳號）和 Instagram。
3. 到 https://publish.buffer.com/settings/api 建立 API 金鑰。
4. **注意：Buffer 金鑰有到期日**，到期後要重新建立並更新。

#### E. 金鑰放哪裡？

- 所有金鑰都填在專案資料夾裡的 `.env` 設定檔（AI 會幫你建立這個檔案，你用文字編輯器打開填入即可）。
- **不要把金鑰貼到聊天視窗，也不要傳給任何人。**

#### F. 讓它每天自動跑（部署到 Render）

本機測試成功後，可以請 AI 帶你把專案放到 Render 雲端，讓它每天自動執行，電腦不用開著。

### 1.5 常見問題／注意事項

| 問題 | 說明 |
|---|---|
| 要花多少錢？ | **OpenAI**：每天產生一次，大約是 1 次網路搜尋＋6 次文字＋3 張圖，通常不到 1 美元（以 OpenAI 帳單為準）。**Render**：兩個自動排程約 US$2／月。**Buffer**：免費方案有「可連接頻道數」和「每個頻道排程佇列篇數」的上限，佇列滿了會排程失敗。 |
| 為什麼沒發出去？ | 1. 沒在 `approved` 打勾。2. 發文時間已經過了（必須是未來的時間，且至少比現在晚 10 分鐘）。3. Buffer 金鑰過期了。請看試算表的 `error` 欄。 |
| 內容可以直接發嗎？ | **請一定要人工核對**。貼文是根據新聞寫的，可能提到真實公司或人物，發之前請確認事實正確。 |
| 圖片有怪怪的字？ | 雖然有要求圖片不要有文字，但偶爾還是會出現，請人工檢查。不滿意可以不打勾。 |
| 三篇講的是同一則新聞？ | 有可能，三種風格有時會挑到同一則新聞，這是已知狀況。 |
| 失敗會一直重試嗎？ | 同一個任務一天最多失敗重試 3 次，避免一直扣錢。超過就等隔天。 |
| 想讓它今天重跑一次？ | 打開試算表的 `_state` 分頁，刪掉那個任務（`generate` 或 `publish`）那一列，它今天就會再跑一次。`_state` 分頁其他時候不要動。 |

## 第 2 部分：給 AI 助手的 prompt

把下面整段複製，貼給你的 AI 程式助手（例如 Claude Code），並確認它是在這個專案資料夾裡執行。

```text
你要幫我啟用這個專案：一個每天自動「搜尋新聞 → 寫 3 種風格行銷文案 → 產圖 → 寫進 Google Sheet → 我勾選 approved → 用 Buffer 排程發到 FB 粉專/IG」的 Python 程式。我不是工程師，請全程用白話、非技術的語言跟我說明，一次只給我一個步驟，等我完成再進行下一步。

【開始前】
1. 先讀 README.md 和 config.py，了解流程與設定。不要修改 legacy/ 資料夾（已不使用）。
2. 建立虛擬環境並安裝套件：
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
3. 只有在 .env 不存在時才執行 cp .env.example .env（已存在就不要覆蓋）。

【安全規則（一定要遵守）】
- 所有金鑰請我自己用文字編輯器直接填進 .env。絕對不要叫我把金鑰貼到聊天視窗。
- 絕對不要印出或顯示 .env 或 Google JSON 金鑰檔的內容（不要 cat，不要 echo）。
- 絕對不要 commit 任何金鑰或金鑰檔。

【帶我逐一完成帳號設定，每完成一個服務就執行 .venv/bin/python main.py check 確認】
1. OpenAI：建立 API key（https://platform.openai.com/api-keys）、確認帳戶有儲值；產圖模型 gpt-image-1 可能需要在 Settings → Organization → General 完成組織驗證。填 OPENAI_API_KEY。
2. Google：Google Cloud 建專案 → 啟用 Google Sheets API 與 Google Drive API → 建立 Service Account → 下載 JSON 金鑰 → 建一個 Google Sheet 並「共用」給 JSON 裡的 client_email（編輯者）→ 從網址 /d/<ID>/edit 取得 Sheet ID，填 GOOGLE_SHEET_ID。
   - JSON 檔放在專案根目錄，並命名為 google-service-account.json（.env 的 GOOGLE_SERVICE_ACCOUNT_JSON 預設就是這個檔名）。
   - 如果下載的檔名不同（例如 autopost-xxxx.json），請改名成 google-service-account.json。.gitignore 只忽略 google-service-account.json 和 *service-account*.json，其他檔名「不會」被忽略。改名後用 git status 確認這個檔案沒有出現在 untracked 清單裡。
   - 你可以只讀 JSON 裡的 client_email 欄位告訴我要共用給誰（例如用 python 只取該欄位），不要印出整個檔案。
3. Cloudinary：註冊免費帳號，取得 Cloud name / API Key / API Secret，填 CLOUDINARY_CLOUD_NAME、CLOUDINARY_API_KEY、CLOUDINARY_API_SECRET。
   - 注意：main.py check 對 Cloudinary 只做 ping，不會驗證上傳權限。請另外用一張 1x1 的 PNG 做一次測試上傳（用 .venv 裡的 cloudinary 套件，從 .env 讀金鑰），成功後立刻用 destroy 刪掉。
   - 如果出現 Request forbidden due to missing permissions (actions=["create"])，代表金鑰權限受限，請我到 Cloudinary Settings → API Keys 產生完整權限的新金鑰。
4. Buffer：IG 必須是商業或創作者帳號；在 Buffer 連接 Facebook 粉專（Page）與 Instagram；到 https://publish.buffer.com/settings/api 建 API key，填 BUFFER_API_KEY。提醒我 key 有到期日，到期要重建。
   - 若同一平台在 Buffer 有多個頻道，check 會列出頻道 id，請我把要用的 id 填到 BUFFER_FACEBOOK_CHANNEL_ID / BUFFER_INSTAGRAM_CHANNEL_ID；否則留空。

【測試流程：任何會花錢或會發文的指令，執行前一定要先問我並得到同意】
依序：
1. .venv/bin/python main.py generate --dry-run   （會花 OpenAI 費用；只印出文案和圖片網址，不寫入 Sheet）
2. .venv/bin/python main.py generate --force     （會花 OpenAI 費用；寫入 Sheet，status=PENDING）
3. 請我到 Google Sheet 的 posts 分頁審核，並在 approved 欄打勾。確認 post_time 是未來時間。
4. .venv/bin/python main.py publish --dry-run    （不花錢、不發文；只列出會排程哪些列）
5. .venv/bin/python main.py publish --force      （會真的排程到 Buffer 並在 post_time 發到 FB/IG）
補充：--force 成功後會記錄「今天已跑過」，所以當天的自動排程不會再跑同一個任務。

【部署到 Render（本機測試成功後）】
- 先確認沒有金鑰檔或 .env 被加入 git，再 push 到 GitHub（push 前問我）。
- Render → New → Blueprint → 選這個 repo，會依 render.yaml 建立兩個 cron job：autopost-generate 和 autopost-publish。
- 兩個 service 都要填環境變數：OPENAI_API_KEY、GOOGLE_SHEET_ID、GOOGLE_SERVICE_ACCOUNT_JSON、BUFFER_API_KEY、CLOUDINARY_CLOUD_NAME、CLOUDINARY_API_KEY、CLOUDINARY_API_SECRET（BUFFER_*_CHANNEL_ID 可留空）。
- Render 上的 GOOGLE_SERVICE_ACCOUNT_JSON 要填「整個 JSON 檔的內容」，不是檔名。請我自己打開檔案複製貼上到 Render 網頁。
- cron 每 15 分鐘喚醒一次，實際執行時間由 config.py 的 GENERATE_TIME / PUBLISH_TIME（台北時間）決定。要改時間請改 config.py，不要改 render.yaml。

【請順便告訴我的已知品質問題】
- 三種風格有時會挑到同一則新聞。
- 雖然 config.py 的 IMAGE_PROMPT_SUFFIX 要求圖片不要有文字，圖片偶爾還是會出現文字，需要人工檢查。
- 文案可能提到真實公司，發文前要人工核對事實。

完成後，用白話總結：我每天要做什麼、在哪裡看錯誤（Sheet 的 error 欄、_state 分頁）、哪些金鑰會過期。
```

## 第 3 部分：啟動選項與可調整的設定

### 3.1 指令一覽

在專案資料夾裡執行（前面都加 `.venv/bin/python main.py`）：

| 指令 | 白話說明 | 會花錢？ | 會真的發文？ |
|---|---|---|---|
| `check` | 檢查所有金鑰有沒有填、各服務連不連得上 | 不會 | 不會 |
| `generate --dry-run` | 試寫 3 篇文案＋3 張圖，只顯示在畫面上，不寫進試算表 | **會**（OpenAI） | 不會 |
| `generate --force` | 立刻產生 3 篇文案＋圖，寫進試算表（不管現在幾點） | **會**（OpenAI） | 不會 |
| `generate` | 自動排程用：只有「已過 08:00 且今天還沒成功跑過」才會執行 | 有執行時會 | 不會 |
| `publish --dry-run` | 只列出「哪些已打勾的貼文會被排程」，不碰 Buffer | 不會 | 不會 |
| `publish --force` | 立刻把已打勾的貼文排程到 Buffer（不管現在幾點） | 不會（Buffer 免費方案內） | **會**，在各列的發文時間發出 |
| `publish` | 自動排程用：只有「已過 15:00 且今天還沒成功跑過」才會執行 | 不會 | **會** |

小提醒：

- 用 `--force` 成功跑過後，當天的自動排程就不會再跑同一個任務。
- 想讓它今天再跑一次：刪掉試算表 `_state` 分頁裡該任務那一列。

### 3.2 自動排程

- 部署在 Render 上的兩個自動任務（`autopost-generate`、`autopost-publish`）**每 15 分鐘醒來一次**。
- 每次醒來，程式自己判斷「現在是不是已經過了設定時間、今天是不是還沒跑過」，是才執行；不是就幾秒鐘結束。
- 真正的執行時間由 `config.py` 的 `GENERATE_TIME`（預設 `08:00`）和 `PUBLISH_TIME`（預設 `15:00`）決定，都是台北時間。
- 因為每 15 分鐘才醒一次，**實際執行最多會晚 15 分鐘**。
- **要改時間，請改 `config.py`，不要改 `render.yaml`。**

### 3.3 可調整的設定（`config.py`）

改完設定後，如果有部署到 Render，需要把修改推上 GitHub，Render 會自動更新。不確定怎麼改，請 AI 幫忙。

| 設定名稱 | 白話說明 | 預設值 |
|---|---|---|
| `KEYWORDS` | 要搜尋的新聞關鍵字，可以放多個 | `["AI Agent"]` |
| `NEWS_LOOKBACK_HOURS` | 只看最近幾小時內的新聞 | `48` |
| `COPY_STYLE_1` | 第 1 種文案風格 | 名稱「專業洞察」，當天 19:00 發 |
| `COPY_STYLE_2` | 第 2 種文案風格 | 名稱「輕鬆有趣」，隔天 12:00 發 |
| `COPY_STYLE_3` | 第 3 種文案風格 | 名稱「行動導向」，隔天 20:00 發 |
| `COPY_PROMPT` | 三種風格共用的寫作規則：字數（150～300 字）、最後一行放 3～5 個 hashtag、不放網址、不捏造事實等 | — |
| `PUBLISH_PLATFORMS` | 要發到哪些平台，可以只留一個 | `["facebook", "instagram"]` |
| `GENERATE_TIME` | 每天產生文案的時間 | `"08:00"` |
| `PUBLISH_TIME` | 每天排程發文的時間 | `"15:00"` |
| `MAX_ATTEMPTS_PER_DAY` | 同一個任務一天最多失敗重試幾次 | `3` |
| `MIN_LEAD_MINUTES` | 發文時間距離現在不到幾分鐘就不排程（太趕或已過） | `10` |

每種文案風格（`COPY_STYLE_1/2/3`）裡面可以改的項目：

| 項目 | 白話說明 |
|---|---|
| `name` | 風格名稱，會出現在試算表的 `version` 欄 |
| `instructions` | 這個風格的語氣、寫法、注意事項 |
| `image_style` | 配圖的視覺風格（用英文寫比較穩定） |
| `post_day_offset` | 產生後第幾天發：`0` 是當天，`1` 是隔天 |
| `post_time` | 發文時間，例如 `"19:00"` |

> **注意**：風格 1 是「當天發」（`post_day_offset` 為 `0`），所以它的 `post_time` 必須晚於 `PUBLISH_TIME`（15:00），否則排程時時間已經過了，會被跳過。

> **風格數量固定是 3 種。** 如果想改成 2 種或 4 種，需要小幅修改程式，請 AI 幫忙修改。

### 3.4 在 Google 試算表裡可以做的事

`posts` 分頁每一列是一篇貼文。你可以直接改的欄位：

| 欄位 | 你可以做什麼 |
|---|---|
| `copy` | 直接修改文案，發文時會用你修改後的內容 |
| `post_time` | 修改發文時間，格式 `YYYY-MM-DD HH:MM`（台北時間），必須是未來時間 |
| `approved` | **打勾才會發**，不打勾永遠不會發 |

其他欄位只用來看，不需要修改：

| 欄位 | 意思 |
|---|---|
| `version` | 這篇是哪一種風格 |
| `image_preview` | 圖片預覽 |
| `sources` | 參考的新聞網址，核對事實用 |
| `status` | `PENDING`＝待審核／尚未排程；`SCHEDULED`＝已成功排程到 Buffer |
| `error` | 最近一次失敗的原因。失敗的貼文會維持原狀態，下次會自動再試 |
| `buffer_facebook_id`、`buffer_instagram_id`、`scheduled_at` | 排程成功後自動填入的紀錄 |

`_state` 分頁是程式記錄「今天跑過沒」用的，平常不要動；只有想讓某個任務今天重跑時，才刪掉該任務那一列。
